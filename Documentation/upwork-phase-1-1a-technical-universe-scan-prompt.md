# Prompt Record — Upwork Phase 1.1A Technical Universe Scan

Verbatim prompt as provided, 2026-09-24:

---

You are executing Upwork Economic Viability Phase 1.1A — Technical Universe Scan.

OBJECTIVE

Scan the broad technical work universe available on Upwork before narrowing into specific niches.

The purpose is to discover where technically difficult, persistent, paid work exists — particularly work where diagnostic uncertainty, specialist knowledge, infrastructure complexity, integration complexity, operational risk, or legacy systems may reduce the effective supply of capable freelancers.

Do NOT assume that WordPress, PHP, JavaScript, server work, or plugins are the answer. They are starting examples only.

SCOPE

Cover the relevant Upwork technical universe, including but not limited to:

- Web development
- WordPress / CMS
- PHP
- JavaScript / TypeScript
- Front-end / back-end
- APIs / integrations
- Plugin / module development
- Databases / SQL
- Linux / server administration
- Hosting / DNS / SSL / email infrastructure
- Cloud / AWS / Azure / GCP
- DevOps / CI/CD
- Docker / containers
- Networking
- Cybersecurity / hardening
- Performance / optimization
- Data engineering
- Web scraping / automation
- Python and other scripting
- Application troubleshooting / debugging
- Legacy systems
- System integration
- SaaS / third-party integrations
- E-commerce / payment systems
- QA / testing / technical debugging
- Other technically relevant categories discovered during the scan

Use Upwork's actual taxonomy, categories, skills, search results, and live job evidence where available rather than inventing an artificial taxonomy.

METHOD

Use the Upwork MCP/live marketplace as the primary discovery source.

Sample each major technical area sufficiently to establish:

1. Whether paid demand exists.
2. Approximate posting frequency / observable supply of projects.
3. Typical project budgets or hourly rates.
4. Typical project duration.
5. Typical proposal competition.
6. Frequency of short projects.
7. Frequency of troubleshooting / repair / diagnostic work.
8. Frequency of technically complex or cross-system work.
9. Whether work appears commodity-like or specialist.
10. Whether recurring demand is visible.
11. Whether jobs commonly require credentials, geography, certifications, or other gates.
12. Whether the work appears suitable for a solo technical freelancer doing short contracts.

Do not confuse the number of search results with true market demand. Record sampling limitations.

IMPORTANT DISTINCTION

Separate:

- raw demand,
- technically difficult demand,
- short-contract demand,
- higher-value demand,
- low-competition demand.

A large market is not automatically an attractive market.

COLLECT RAW EVIDENCE

For each major technical area, record representative observations rather than cherry-picking exceptional jobs.

Where practical, capture:

- sample size
- budget distribution
- duration distribution
- proposal distribution
- recurring problem types
- common skills
- common client requirements
- examples of technically difficult jobs
- examples of low-budget/commodity jobs
- examples of short jobs

Also record obvious market boundaries and overlaps. A client-facing problem may belong to several technical domains.

OUTPUT

Produce a structured Phase 1.1A report containing:

1. Executive findings
2. Technical-universe taxonomy used
3. Evidence by technical area
4. Cross-market observations
5. Areas requiring deeper investigation
6. Areas that appear obviously commodity/poor-economics and why
7. Areas where evidence is insufficient
8. Raw evidence/statistical limitations
9. Dataset/search methodology
10. Handoff dataset for Phase 1.1B

Do NOT declare winners.

Phase 1.1A is discovery, not ranking.
