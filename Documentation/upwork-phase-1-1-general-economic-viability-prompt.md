# Phase 1.1 — General Economic Viability

Read the existing Upwork Phase 1 economic report and its evidence before doing anything else.

The existing report is the baseline. Do NOT repeat tests that have already been completed. Extend the evidence only where Phase 1.1 still has material unknowns.

## Objective

Determine whether there is a realistic path to making actual money on Upwork as a new solo WordPress technical freelancer.

This is an empirical investigation, not a theoretical marketplace analysis.

Do not assume that only attractive or conventional jobs are worth pursuing.

A new freelancer may have greater practical access to technically unpleasant, urgent, confusing, low-status, or poorly specified work because experienced freelancers may avoid it. Treat this as a hypothesis to test, not as an assumption.

## Critical principle

Do NOT optimize the investigation for finding "good jobs."

Measure the accessible market, including jobs that are:

- ugly
- boring
- poorly described
- low budget
- urgent
- technically difficult
- legacy
- broken
- troubleshooting-heavy
- unattractive to ordinary developers

The question is whether some subset of these jobs can produce profitable work for Marc.

# 1.1-B — The "Shit Work" Market

Explicitly investigate technically unpleasant work that may be overlooked by competitors.

Look for recurring categories including, but not limited to:

- 404 errors
- redirect problems
- broken layouts
- mobile display failures
- CSS/theme problems
- plugin conflicts
- failed migrations
- PHP errors
- WordPress crashes
- white screens
- Cloudflare problems
- WooCommerce failures
- malware/security cleanup
- speed/performance failures
- broken API/integration work
- legacy WordPress problems
- abandoned customizations
- urgent one-off fixes

Do not assume these categories are valuable.

Measure:

- frequency;
- project value;
- competition;
- client quality where available;
- apparent urgency;
- duration;
- technical complexity;
- repeatability;
- suitability for a short fixed-scope job.

Determine whether technically unpleasant work has characteristics that could make it more accessible to a new freelancer.
