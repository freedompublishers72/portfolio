# Upwork Economic Viability (Phase 1) — Prompt Record

Date: 2026-09-24
Task type: Economic analysis (read-only; no platform writes)

The following is the exact prompt used for this task, preserved verbatim:

---

PHASE 1 — ECONOMIC VIABILITY
============================

Determine whether freelance-platform work is economically viable for Marc as
a solo, location-independent WordPress/PHP engineer.

This phase has TWO distinct analyses:

A. GENERAL ECONOMIC VIABILITY
B. BID-VS-PROJECT ECONOMICS

Do not assume that obtaining work is possible. The purpose of this phase is
to determine whether the underlying economics work.

--------------------------------
A. GENERAL ECONOMIC VIABILITY
--------------------------------

Establish Marc's practical economic constraints:

- Need for relatively rapid income generation
- No assumption of a salaried 9–5 job
- Solo operator
- Location-independent
- Limited tolerance for prolonged unpaid platform activity
- Short contracts preferred
- Project/fixed-price work preferred
- Work should ideally be completable within hours to several business days
- Avoid business models requiring substantial upfront capital
- Avoid recurring paid platform privileges as a prerequisite
- Avoid dependence on building a reputation for many months before becoming
  economically viable

Do not invent personal financial figures that have not been provided.

Determine what a viable acquisition channel would need to produce in terms of:

- minimum viable project value
- acceptable acquisition effort per project
- acceptable unpaid proposal/research time
- required number of successful projects per month
- sustainable effective hourly return

Where an exact threshold cannot be established from available information,
identify it as an assumption requiring later testing.

--------------------------------
B. BID VS PROJECT ECONOMICS
--------------------------------

Investigate the economics of bidding for freelance projects.

The central question is:

"Does the expected value of winning projects justify the time, competition,
platform costs, Connects/bids, proposal effort, and unsuccessful bids?"

For each relevant marketplace/test dataset, determine:

1. Typical number of bids/proposals per project.
2. Typical project value.
3. Distribution of project values.
4. Bid/proposal cost.
5. Platform fees.
6. Paid membership/verification costs, if applicable.
7. Cost of Connects or equivalent bidding currency.
8. Time required to discover and evaluate a project.
9. Time required to prepare and submit a proposal.
10. Typical/observed win rate where actual evidence exists.
11. If no reliable win-rate data exists, model multiple sensitivity scenarios
    rather than inventing a rate.

Calculate expected acquisition economics under multiple win-rate scenarios,
for example:

- 1%
- 2%
- 5%
- 10%

For each scenario calculate:

- bids required per successful project
- proposal/acquisition time per successful project
- bidding/Connect cost per successful project
- platform fees
- gross project revenue
- net revenue before tax
- effective hourly return after unpaid acquisition time

Run the analysis separately for:

- low-value projects
- median-value projects
- higher-value projects

Do not assume that higher-value projects are accessible to a new account.
Record eligibility restrictions separately.

--------------------------------
C. COMPETITION / TIME DECAY
--------------------------------

Where data permits, investigate how rapidly projects become crowded.

Measure:

- bids/proposals shortly after posting
- bids/proposals after 1 hour
- after 6 hours
- after 12 hours
- after 24 hours

Determine whether early access materially changes the number of competitors.

Distinguish observed data from inference.

--------------------------------
D. BOOTSTRAP TEST
--------------------------------

Answer:

"Can a new solo freelancer enter this marketplace and reach meaningful
revenue without first spending substantial money or months accumulating
platform reputation?"

Include:

- initial cash requirement
- initial bid/Connect requirement
- required memberships
- verification requirements
- reputation requirements
- geographic restrictions
- automation restrictions
- minimum viable proposal volume

--------------------------------
E. SENSITIVITY ANALYSIS
--------------------------------

Model how the economics change when:

- average project value changes
- win rate changes
- proposal time changes
- number of bids changes
- platform fees change
- available project volume changes

Do not produce a subjective score or declare a platform "best."

--------------------------------
F. REQUIRED OUTPUT
--------------------------------

Produce:

1. Economic assumptions
2. General viability findings
3. Bid-vs-project calculations
4. Competition/time-decay findings
5. Bootstrap requirements
6. Sensitivity analysis
7. Major economic failure points
8. Unknowns requiring real-world testing
9. Raw evidence supporting each conclusion

Clearly distinguish:

FACT
OBSERVED DATA
CALCULATION
ASSUMPTION
UNKNOWN

Do not recommend a platform yet.

This phase is strictly an economic viability test. The purpose is to determine
whether the economics justify proceeding to later discovery phases at all.
